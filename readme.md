# Poem Template

A starter template for building a REST API in Rust with [Poem](https://github.com/poem-web/poem) and [poem-openapi](https://github.com/poem-web/poem-openapi). It ships with a small Todo API, Swagger UI, typed error responses, and a `tasks.py` dev task that restarts the server on file changes.

## Project structure

```
.
├── Cargo.toml          # Package metadata and dependencies
├── Cargo.lock          # Locked dependency versions (generated by cargo)
├── LICENSE             # License text (0BSD)
├── tasks.py            # Invoke tasks, e.g. `invoke dev`
├── agents.md           # Guidelines for AI coding agents
├── claude.md           # Guidelines for Claude Code
└── src/
    ├── main.rs         # Entry point: builds the server, routes, and logging
    ├── controller/     # OpenAPI endpoints, one module per resource
    │   ├── mod.rs      # API tags shared by all controllers
    │   └── todo.rs     # TodoController: GET /todo, POST /todo
    ├── dto/            # Request and response types exposed in the API
    │   ├── mod.rs
    │   ├── get_todo_api.rs    # GET /todo response types
    │   └── post_todo_api.rs   # POST /todo request and response types
    ├── error/          # Error handling
    │   ├── mod.rs
    │   └── service.rs  # ServiceError enum and the `api_errors!` macro
    └── types/          # Shared types used across modules
        ├── mod.rs
        └── responses.rs # BaseResponse<T> (success) and ErrorResponse
```

How the pieces fit together:

- **`main.rs`** mounts the OpenAPI service under `/api` and Swagger UI under `/docs`, then listens on `0.0.0.0:3000`.
- **`controller/`** holds the endpoints. Each controller is an `impl` block annotated with `#[OpenApi]`.
- **`dto/`** holds the structs that are serialized to and from JSON. They derive `Object` (for the request/response body) and `ApiResponse` (for the status codes).
- **`error/`** defines `ServiceError`. The `api_errors!` macro generates an error enum for an endpoint and maps each `ServiceError` variant to an HTTP status. Anything unmapped becomes a `500`.
- **`types/`** holds generic wrappers. `BaseResponse<T>` wraps success data with a message, and `ErrorResponse` wraps error messages.

## Prerequisites

- [Rust](https://www.rust-lang.org/tools/install) with `cargo`
- Python 3 with [`invoke`](https://www.pyinvoke.org/) and [`watchdog`](https://github.com/gorakhargosh/watchdog) (for `tasks.py`)

Install the Python tooling either globally, in a virtual environment, or as uv tools:

```sh
# pip (global or in a venv)
pip install invoke watchdog

# or uv
uv tool install invoke
uv tool install watchdog
```

`invoke` must be importable by Python. `watchdog` only needs to provide the `watchmedo` command, so installing it as a uv tool is fine.

## Running the app

### Development (auto-restart)

From the project root:

```sh
invoke dev
```

This runs `watchmedo auto-restart` around `cargo run`. It:

- watches `.rs` and `.sql` files under the project, recursively
- waits 5 seconds after a change before restarting (debounce)
- keeps watching when the build fails, so you can fix the error and save again

Changes to `Cargo.toml` are not watched. Restart `invoke dev` after editing dependencies.

### Plain run

```sh
cargo run
```

### Listing tasks

```sh
invoke --list
```

### Endpoints

Once the server is running:

| What              | URL                                      |
| ----------------- | ---------------------------------------- |
| Swagger UI        | http://localhost:3000/docs               |
| GET todo (stub)   | http://localhost:3000/api/todo           |
| POST todo         | http://localhost:3000/api/todo           |

`GET /api/todo` always returns `404` with `Todo item not found!`, as a placeholder for a real lookup. `POST /api/todo` logs the request body and returns `204`.

Log level defaults to `debug`. Set `RUST_LOG` to override it.

## Using this template

There are two ways to start a project from this template.

### Option 1: Clone and work on the template directly

Use this if you want to keep the template's history or experiment with it.

```sh
git clone <this-repo-url> my-project
cd my-project
```

Then update the values that are specific to your project:

1. `Cargo.toml`: change `name` under `[package]` (and `version` and `description` if needed).
2. `src/main.rs`: change `API_TITLE`, `API_VERSION`, and `API_IP` as needed.
3. Remove the `.git` directory and run `git init` if you want a fresh history.

### Option 2: `cargo new` and copy the source (recommended)

Use this if you want a clean project that always picks up the newest dependency versions. Copying only the source avoids pinning the template's old versions in `Cargo.toml` and `Cargo.lock`.

```sh
cargo new my-project
cd my-project
```

Copy the template's `src/` directory and `tasks.py` into the new project, replacing the generated `src/main.rs`:

```sh
cp -r /path/to/poem-oai-test-macro/src/. src/
cp /path/to/poem-oai-test-macro/tasks.py .
```

Then add the dependencies without version pins, so cargo resolves the latest versions:

```sh
cargo add poem
cargo add poem-openapi --features swagger-ui
cargo add serde --features derive
cargo add tokio --features rt-multi-thread,tracing
cargo add color-eyre log thiserror tracing tracing-error tracing-subscriber
```

Check the build and start the dev server:

```sh
cargo build
invoke dev
```

The `cargo new` command already sets `edition` for you. Make sure it is `2024` in `Cargo.toml`, since the template code uses that edition.

Finally, update `API_TITLE`, `API_VERSION`, and `API_IP` in `src/main.rs` to match your project.

## Adding a new endpoint

1. Add request and response types in `src/dto/`, and register the module in `src/dto/mod.rs`.
2. Add an `#[OpenApi]` impl in `src/controller/`, or add methods to an existing one.
3. Declare the error variants with `api_errors!`, using a `ServiceError` variant name.
4. Register the controller in `main.rs` if it is a new one.
